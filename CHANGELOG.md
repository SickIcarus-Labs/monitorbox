# Changelog

What changed in each version of the MonitorBox app, in plain words. Every change that reaches a user adds a line under **Not on stable yet**. When a version is promoted to the stable channel, that heading is renamed to the version and a new empty one is started.

Versions move through three channels: **dev** (newest, may be rough), **beta**, then **stable**. A version listed here may not have reached your channel yet; Settings, Updates shows which one you follow.

## Not on stable yet

- **1.6.38** (#314) "Update all sites" now reloads the page when this box updates itself. Before, the page said "This box is restarting" and stayed there until you refreshed by hand; now it shows "Restarting…" and comes back on its own, like any other app update.
- **1.6.37** (#314) The "Update all sites" button now shows only when an update is waiting at this box or at a linked site. It used to show whenever a site was linked.
- **1.6.36** (#311) History now names every port in a long Port errors stretch. A stretch used to keep only the ports named when it began, so a port that started rising later in the same stretch (like Guest Room, Port 8 at Broad Leaf) was never mentioned. Ports that join are now added to the reason, for example "...; also Guest Room, Port 8", up to the same length limit.
- **1.6.35** (#312) The Updates page now has a "What changed" link on the MonitorBox app: when an update is waiting it lists what changed in every version between yours and the one on offer (newest first, in plain words); when you are up to date it shows what your version brought. The notes travel inside the release itself, so MonitorBox does not need to reach any other site. Versions released before this one carry no notes. Modules have no changelog yet, so only the app has the link.
- **1.6.34** (#314) New "Update all sites" button on the Updates page of the main box (shown when at least one site is linked). It asks every linked site to install what is waiting, without waiting for them to finish, then installs here last, and lists each site as asked, installing, done, or did not update (with the reason). It does what pressing "Update all" on each site would do: items pinned to a version stay put, and nothing happens unless you press it. A site that is not linked is skipped.
- **1.6.33** (#313) The "Update all" button on the Updates page now shows whenever at least one update is waiting (the app or a module), not only when there are two or more.
- **1.6.32** (#310) When MonitorBox updates itself (automatic updates on), the bell now says so: "MonitorBox updated itself from 1.6.31 to 1.6.32." for the app, and the same for each module. Tap the note to clear it; notes also go after a week. An update you start yourself does not add a note.
- **1.6.31** (#292) A device plugged into an access point's own Ethernet port (a computer on the back of an in-wall access point, say) now shows up on the network map and in the port watch, instead of being read and then listed as "no link". Ports that share a name on one device ("Data" on three ports) are now watched separately, with the port number added to the name, so they can no longer share one history.
- **1.6.30** (#292) The list of other interfaces is back on the Port errors page, as its own section under Which ports: "7 other interfaces are read but not counted (no link)", with the names listed inside. The explanation of why a device was read on its own stays out of it, and only shows for a switch that was not matched.
- **1.6.29** (#292) The long "other interfaces are read but not counted" list is gone from the Port errors page. It is now one line at the bottom of Which ports ("N other interfaces are read but not counted"). The explanation of why a device was read on its own, with the names UniFi uses, is only shown for a device that looks like a switch and was not matched to a UniFi device while UniFi has devices, which is the case it was built to explain.
- **1.6.28** A counter that goes round is no longer taken for a reset. Some network cards report a 16-bit drops counter, which starts again after 65,535; at around a hundred a second that happens every 10 to 15 minutes, so the port (Arrrrr3's eno3) kept starting over and never finished learning. A counter that falls from just under 65,536 (or 4,294,967,296) now counts as having gone round, and its total carries on. A fall from anywhere else is still a reset.
- **1.6.27** (#292) The network map now shows SNMP switches that UniFi does not know, with their ports, speeds, the neighbour on each port (from LLDP), how many devices sit behind a port (from the addresses it has learned) and the links between switches. A switch UniFi also lists is still drawn once. With no UniFi connection at all the map is built from SNMP switches alone.
- **1.6.26** The Port errors page says how long a port has been read as hours and days when that is clearer: "17 h 26 min of readings" instead of "1046 min of readings".
- **1.6.25** When a port's counter goes backwards (and its history starts again), the Port errors page now says from what to what, for example "from 24,282 down to 31". Found on a server card whose packet-drops counter kept stepping back.
- **1.6.24** (#292) Port errors now work with SNMP switches alone, with no UniFi connection at all. An SNMP switch is read directly: errors, packet drops, link drops and speed per port, with the same learning period and rules. Ports with a neighbour or several addresses behind them count as links; the others are treated as clients' ports, where only errors count. Ports read over SNMP use the speed the device reports, so the minimums scale with the link. The map for SNMP-only networks comes next.
- **1.6.23** (#292) The Port errors line now reads "all 51 ports look normal" (was "no port is getting worse") and, while a new box is still learning, "learning what is normal (X of Y ports ready)". Leftover virtual interfaces that are not a cable at all (dummy0, lxdbr0, sit0, virbr0, docker0, tunnel stubs) are no longer listed under "other interfaces".
- **1.6.22** (#292) Wording: alerts, the map and the Port errors page now say "packet drops" (link drops stay "link drops"), so the two are not confused. The network map footer says packet drops are usually congestion, not a fault, and that errors are the better sign of a bad cable. The docs note that link drops are more common on Wi-Fi than on Ethernet.
- **1.6.21** (with SNMP 0.3.6, #292) Network cards of SNMP servers (Goliath, Arrrrr3, Apollo...) are now handled like switch ports. A card with a link counts as a port in use and a card with no link is read quietly; the Port errors page says how many of the counted ports are server cards. Link drops are counted on them too: the module reads when each link last changed and the box counts a drop when a link went down, or went down and up again between two readings (a device restart is not a drop). A card that belongs to a bond or team says so in the alert ("eth1 (in bond0)"), and the bond, team or VLAN itself is no longer listed as a port, because it only repeats the cards under it. The device's own stack table decides this, not names. Update the SNMP module too.
- **1.6.20** (#292) The gateway's way out to the internet (the port to the modem) is now a port like any other: watched, counted, and shown on the map as "Internet (WAN)" with its real speed. UniFi calls that port an "uplink" and the map left out uplinks on the assumption they lead to a parent switch, but a gateway has none, so its modem port was listed nowhere and its speed was unknown. The box then treated it as a 1 Gbit port, which made 136 receive errors an hour on a 5 Gbit link look like news. Packet drops and link drops count on it, as on any uplink.
- **1.6.19** (#292) The switch end of a Wi-Fi access point's cable is now watched and counted. An access point reports no ports of its own, so the map skipped the whole link and the switch port it plugs into (Aggregation ports 7, 8 and 16) was read but not counted: the map footer said 50 ports and the Port errors page 47. These are uplinks, so packet drops and link drops count on them too.
- **1.6.18** (#292) The network cards of SNMP servers (Apollo, Goliath, Arrrrr3...) now raise an alert for packet drops as well as errors. 1.6.13 limited packet drops to uplinks, links between switches and servers, but only counted a port as a server port when the map said so, which left the cards the box reads over SNMP out. Their errors always alerted.
- **1.6.17** (#316) A port keeps what it has learned when the device on it sleeps. A Mac that wakes for a backup and goes back to sleep takes its link down, the map stops showing the port, and 30 minutes later its history was cleared, so every wake started a new half hour of learning (Office Port 2 stayed at a few minutes of readings). A port the map showed in the last day now keeps its history; interfaces that never were ports (leftover readings of a switch that is now matched to its UniFi device) still clear after 30 minutes.
- **1.6.16** (#292) When UniFi gives no device list for a round (slow, or just after a restart), the box now leaves everything as it was instead of guessing. Without that list nothing could be matched, so every SNMP switch (Switch 2, the Gateway) was read as a server: the Port errors page said "matches 0 of 0 UniFi devices". That is an outage, not a different network.
- **1.6.15** (#292) A bond or team, a port-channel and a VLAN sub-interface (bond0, team0, Po1, eth0.100) is no longer listed as a port of its own on an SNMP server. It only repeats the network cards under it, so one bad cable showed up as several rows. The cards that make up a bond are still watched on their own.
- **1.6.14** (with SNMP 0.3.5, #292) An SNMP connection is now matched to its UniFi device by the hardware addresses of its network interfaces, before trying names. The SNMP module reports each interface's address (shortened, like the UniFi report) and the box looks for the one UniFi device that has it, so a switch is recognised whatever the connection is called and whatever address it is reached on. Names remain the fallback. Update the SNMP module in Settings, Updates too.
- **1.6.13** (#292) Dropped packets now only raise an alert on uplinks, links between switches and servers. Both sites alerted at night on Apple TV ports (transmit drops: Theater Port 2, Guest Room Port 8, Master Bedroom Port 4): a client in standby backs up its port, which is not a fault. Errors still alert on every port. The "other interfaces" explanation also shows the exact simplified names it compared ("Switch 2" as "switch2"), to find out why Switch 2 and the Gateway are still read as servers.
- **1.6.12** (#292) When an SNMP connection is read as a separate device (a "server") even though it may really be a UniFi switch, the "other interfaces" list now says why: what its address, its name and the name it reports over SNMP matched, and what UniFi calls its devices. 1.6.11 still left Switch 2, the Gateway and Aggregation read twice on one box, and the names alone could not show why.
- **1.6.11** (with SNMP 0.3.4, #292) An SNMP connection is now matched to its UniFi device by the name the device gives itself over SNMP ("Switch2", "BroadLeaf"), ignoring spaces, punctuation and capitals, when the address and the connection's name do not match. 1.6.10 only tried the connection's name, which did not line up for Switch 2, the Gateway or Aggregation, so those three were still read a second time as if they were servers (53, 30 and 468 interfaces). The first read tells the box who the device is; from the next round it is read once, as the switch, and its server-style readings are dropped.
- **1.6.10** (#292) A switch that is both a UniFi device and an SNMP connection is now read once. The box used to recognise the pairing only by IP address; when the SNMP address is not the one UniFi lists (seen on Switch 2 and the Gateway: 53 and 30 interfaces read a second time, as if they were servers) it read the same device twice. It now also matches by name, when exactly one UniFi device has that name.
- **1.6.9** The network map's footer now counts switch ports as well as clients: "12 UniFi devices · 47 switch ports in use · 29 Ethernet clients · 100 Wi-Fi clients". "29 wired clients" and "47 ports" read like the same kind of number and were not (a bonded server is one client on two ports; a cable between switches is two ports and no clients), so each now says what it counts. The port number is the same set of ports the Port errors page counts, and it shows even when the port watch is off. The footer also carries the reminder "an uplink between switches counts as 2 ports and 0 clients".
- **1.6.8** (#292, first step) The "other interfaces are read but not counted" list on the Port errors page now says which device they come from, how many each, and how long ago they were last read ("Aggregation (snmp:...): 574, last read 3 min ago"), so it is clear whether they are still being read or are leftovers. Leftovers go: an interface the map does not show, with no new reading for 30 minutes, is forgotten.
- **1.6.7** A Port errors alert for a port with a device on it now names the device, taken from the controller's client name ("Theater, Port 2 (Apple TV): drops rising ..."), on the alert and on the Port errors page. Links between switches are unchanged: they already say what the other end is doing. The History page also keeps up to 400 characters of each reason (it was 160, which cut Broad Leaf's alert off at "other end (Aggregation, S"), and shows "…" when something is still cut.
- **1.6.6** (with SNMP 0.3.3) Port errors reads only the ports you watch. On a switch with hundreds of port-channel and virtual interfaces (Aggregation has 570+) it was reading every one of them every 10 seconds, about 5 s of work each time; now it asks for just the 17 or so that matter, and the other interfaces drop off the "read but not counted" list. The count is also right straight after a restart (it showed 621 until the map was rebuilt, then 47), and "Which ports" stays open while the page refreshes.
- **1.6.5** Port errors is less jumpy about drops, and the minimums now follow the port's speed. A port has to gain at least 10,000 drops in 15 minutes on a 1 Gbit link before it counts (it was 1,000, which an Apple TV port tripped), and 20 errors; the minimums scale with the link (10 Gbit: 100,000 drops and 200 errors; 100 Mbit: 1,000 drops and 20 errors, the lowest they go). A port must still be at least five times its own normal. Link drops are not scaled. The rules are updated in docs/PORT-WATCH.md.
- **1.6.4** Port errors page: "Which ports" now says how many minutes of readings each port has and whether its counter went backwards (which starts its learning again), and a second list names the other interfaces the watch reads but does not count (so a server with hundreds of virtual interfaces can be seen and dealt with). SNMP 0.3.2: the first reading of a switch no longer asks every listed interface for all its columns, only for the two traffic counters first, then the rest for the interfaces that have them (the first read of one switch took 17 seconds).
- **1.6.3** Settings no longer stalls when one of its reads gets no answer (seen once after an update: first entry sat for 30 seconds, and the box's own timings showed no slow request). Each of the nine reads Settings makes gives up after 12 seconds and asks once more on a fresh connection. Changes you make are never retried. The Port errors page now has a "Which ports" list showing exactly what its port count is made of.
- **1.6.2** The performance report now lists the slow module calls (over 3 seconds) with the connection each one was for ("snmp.counters for <name> 16.9 s, 4 min ago"), so a slow device can be named instead of guessed at. It is kept in memory only, like the rest of the report.
- **1.6.1** Port errors keeps what it has learned when the controller answers with only some of its devices, or when the settings file cannot be read for a moment (before, either could wipe the history and restart the half hour of learning). Only a port gone from a device that answered, a device not seen for a day, or switching it off by hand forgets history. The map now says how many ports the watch covers and what they are (the ports in use plus both ends of every link between devices).
- **SNMP 0.3.1** (no app change) The first SNMP reading of a device's ports no longer walks every table across every interface: it reads the interface names once, then only the real interfaces' numbers by index, so a server with hundreds of container interfaces answers in a fraction of the time (the first read took up to 20 seconds). Table walks also ask for 40 rows per request instead of 20.
- **1.6.0** Link awareness. An uplink, a link between devices or a server's network card that has been up for an hour is expected to stay up; if it goes down for a minute the Port errors item shows a yellow heads-up ("link is down (was up, down for N min)", one line per cable). A card that was never up (an unplugged one) stays quiet, ordinary client ports are never watched this way, and "Not coming back" on the Port errors page forgets a link until it lights again. SNMP module reports each interface's link state (0.3.0). The rules for all of port monitoring are now written down in docs/PORT-WATCH.md.
- **SNMP 0.2.9** (no app change) Port and interface counters are much faster to read. The first reading (and one every ten minutes) learns which interfaces are real; the readings in between ask for just those interfaces' numbers, a few dozen at a time, instead of walking every table again. A server with hundreds of container interfaces no longer takes seconds per reading. A link that negotiates down to a lower speed still shows at once.
- **1.5.1** On the network map, every port now has an "alert" tick (on by default) in place of the "known issue" link: untick it to keep watching a port but never be told about it. The Port errors page and the map are the same setting. The Port errors page and its check now count the ports in use, the same ports the network map shows (empty ports are still read quietly, so a port plugged in later has its history). The explanation under "Watch for rising port errors" no longer says it is off by default.
- **1.5.0** Port errors is on by default on any box that has a switch to read (a UniFi or SNMP login), and starts quietly while it learns. It has its own page now: an Enable / Disable button (switched off by hand stays off), a link to the network map, the ports that are rising with an "Alert on this port" tick each (on by default; unticked ports are still watched and shown, they just never raise the Degraded heads-up), and a list of the ports not alerting. The check reads "Port counters", and Mark critical, Mark expected down and Stop watching are hidden there.
- **1.4.3** The network map page opens at once. It shows the last map straight away (kept on disk, so it works right after a restart too) and refreshes it in the background when it is more than a minute old, instead of waiting for a fresh scan of the network.

## 1.0.1 to 1.4.2

- **1.4.2** Port errors no longer turns Unknown after a restart. For the first three minutes it shows "checking" ("waiting for the first port readings") while the switch counters come in, and what each port normally does is now saved (every five minutes, up to a day, in the app's data folder) so a restart does not start the 30 minutes of learning again. Turning the watch off deletes the saved history.
- **1.4.1** Start-up fix on top of 1.4.0 (1.4.0 was never offered: its release check failed once, when all eight modules were started at the same instant on the small test machine). Modules now start four at a time and have 20 seconds to say hello.
- **1.4.0** Faster, calmer start. After a restart the modules start all at once instead of one after another, and a check whose module is still coming up shows "checking" instead of "Unknown, the snmp module is not running", then runs again the moment its module answers. The page also opens with the readings from before the restart, marked "(last reading before the restart)", until each check's own fresh answer replaces its reading (two minutes at most; readings older than ten minutes are not used, and alerts never act on them). A module that really cannot start is still reported after 90 seconds.
- **1.3.0** Port watch also watches the network cards of SNMP servers (errors and drops per card, read every 30 seconds while the watch is on). A server card is matched by its hardware address to the switch port it is plugged into, so that port's line shows what the server's side of the cable sees ("other end (apollo, eth0): ..."). Marking a switch port as a known issue silences the server card at the other end of that link too. A card that is not matched to a switch port still raises the heads-up in History and alerts, but cannot be marked from the map.
- **1.2.0** Port watch can read errors and drops over SNMP. A switch that is also an SNMP connection gives its receive and transmit errors and drops straight from the interface, which is exact and works for switches that are not UniFi. UniFi's own counters are used for everything else, and one device never mixes the two. Link drops still come from UniFi. (SNMP module 0.2.8.)
- **1.1.3** Port watch shows the other end of a link: a port with rising errors also says what the port at the far end is seeing ("other end (Aggregation, Port 3): 0 receive, 0 transmit an hour"), so a one-direction problem is plain at a glance.
- **1.1.2** Port watch says what kind of errors: receive and transmit counted apart ("29,000 receive, 68 transmit"), and how busy the port was while they happened ("carrying about 4.1 Gbit/s, peak 9.2"). Receive errors point at the cable, optic or the far end; transmit errors and drops point at a port backing up.
- **1.1.1** Port watch: link drops are only reported for uplinks, links between switches and servers, not for ports with a laptop or TV on them (they drop whenever the device sleeps). A port is also compared with the worst 15 minutes it has had in the last day, so errors that only come under a big transfer are not flagged each time.
- **1.1.0** Watch for rising port errors (off until you tick it, on the Network map page). MonitorBox learns what is normal for each switch port and shows a yellow heads-up, never red, when a port's errors, drops or link drops climb well above that. A port you mark "known issue" keeps its numbers but never raises anything. It needs about half an hour of readings before it says anything, and starts over after a restart of the box or of a switch.
- **1.0.1** The busiest-client card says "The network is quiet" when nothing is busy, not "The wired LAN is quiet": it watches wifi devices too.

## 1.0.0 and 0.83.18 to 0.83.22 (stable, October 25)

- **1.0.0** Version number only, nothing else changed: MonitorBox is in use, so it is 1.0. From here the middle number moves for new abilities and the last for fixes.
- **0.83.22** The Sites card counts the sites it watches even when there is only one ("1 of 1 up"), like the other cards. A row with a long name and a middling detail (a camera called "Camera Garage") now gets two lines instead of a cut-off one.
- **0.83.21** A camera that UniFi Protect and Scrypted both watch is one camera: both say it is down, it is Down; they disagree (one says down, the other says fine), it is only Degraded, since one source may be the one acting up. One attention line and one alert per camera, and the detail says the other source reports it fine.
- **0.83.20** Cards fold their many alike items: cameras, switches and access points, and VPN tunnels each sit under one heading per source (for example "UniFi Protect cameras"). A problem inside opens its heading by itself. A camera that two sources both report counts once, so the Cameras summary counts cameras instead of 19 of 19.
- **0.83.19** Choose what counts as critical: a Critical tick on each item's detail and on each server's settings page (and for Portainer as a whole). When a critical thing is Down, the whole banner goes red.
- **0.83.18** Every camera, UniFi device and VPN tunnel is its own item, so one that is offline shows as Down by name instead of making a shared item ("Cameras", "UniFi", "Scrypted") only Degraded. Existing boxes are split automatically; the recorder and storage stay together as "UniFi Protect", and the old all-cameras summary checks are dropped because each camera now says its own state.

## 0.83.11 to 0.83.17 (stable, October 25)

- **0.83.17** Busiest client: the gateway, switches and access points are never crowned (the gateway could show up as the "busiest client" because it appears in its own flow log).
- **0.83.16** Tapping a traffic graph: a big download the gateway has not named yet (a game download, for example) is now listed as internet traffic instead of "not matched yet".
- **0.83.15** Alerts: choose what sends an alert. Tick Down, Degraded, Unknown and Restored. Unknown is off unless you turn it on. A UPS running on battery always alerts.
- **0.83.14** Site name: the welcome page asks "What do you call this site?". When a managed site has no name of its own, the main box offers to set one (never over a name you chose). Phone (Home Assistant) alerts end with the time at the site, for example "(1:36 PM CDT at Riverside)".
- **0.83.13** Alert emails show the time in the box's own time zone instead of UTC.
- **0.83.12** Alerts use the site name set under Settings, Sites, not the computer's name.
- **0.83.11** Busiest client: cameras are recognised by hardware address and name, so the Cameras tick works; links between switches are never crowned.

## 0.83.10

- Traffic graphs no longer show spikes and gaps for devices that only refresh their counters every few seconds.
